1. Executive Summary

TrustNode already has the correct backbone for production: edge-first durable collection, outbox sync, ingest APIs, tenant-aware cloud schema, and live/historical split. The best strategy is to avoid a big rewrite and add a lean control plane for customer, edge, licensing, and URL tenancy management.

Strength

Edge-First Reliability

Local persistence and outbox allow operations during cloud/network outages.

Strength

Ingest Idempotency

Cloud ingest with scoped tokens and deduplication supports safe retries.

Gap

Commercial Control Plane

Need central tenant/customer/edge/license lifecycle and activation workflows.

3. Security & Isolation Topology

IT/OT Security Boundary (Zones and Conduits)

flowchart TB subgraph OT_ZONE[OT Zone] PLC[PLCs/Meters] EDGE[Edge Host] PLC --> EDGE end subgraph VPS_DMZ[VPS / DMZ] WAF[WAF + Rate Limiting] API[Ingest + Control API] WAF --> API end subgraph CLOUD_ZONE[Cloud Zone] DB[(Postgres/Supabase)] SA[(Security Audit Logs)] end EDGE -- outbound HTTPS only --> WAF API --> DB API --> SA CUSTOMER[Customer Browser] --> WAF ADMIN[Developer Admin + MFA] --> WAF

Mandatory Security Controls

  • No inbound internet traffic into edge nodes.
  • Separate human auth and machine/device auth.
  • Tenant scope checks at token + API + query layers.
  • RLS for all user-facing data tables.
  • MFA for admin and privileged roles.

Data Protection Model

  • Immutable raw telemetry for auditability.
  • Latest snapshot for low-latency dashboards.
  • Per-tenant logical separation and policy boundaries.
  • PITR backups + restore drills for resiliency.

4. Customer URL and Licensing Strategy

Recommended: wildcard subdomain tenancy on your VPS/frontend proxy:

customer-a.trustnode.lsapps.app, customer-b.trustnode.lsapps.app

Map host header → tenant context in backend; deny cross-tenant access by default.

Control Plane Components

  • Customers/Tenants registry
  • Edges registry + activation workflow
  • Licenses + module entitlements
  • User memberships + role model
  • Password recovery + security events

6. Commercial Readiness Outcomes

Performance Targets

  • Local edge live update: <= 1s
  • Cloud live update p95: <= 2s
  • Outbox depth bounded under normal connectivity
  • No cross-tenant data exposure

Commercial Targets

  • Per-customer onboarding and activation
  • Per-module licensing enforcement
  • Per-customer URL and role-based view control
  • Admin-level recovery and account operations
